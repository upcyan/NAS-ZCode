# 上游版本同步调研：3.14.3 vs 官方 CDN 3.14.5

> 调研时间：2026-10-09 · 结论：**暂保持上游 3.14.3**（GitHub 公开最新），3.14.5 无法复现构建

## 事实

| 来源 | 版本 | 可否用于打包 |
|---|---|---|
| GitHub `zai-org/ZCode` main / tag | **3.14.3**（`29628c9acd`） | ✅ 可（CI 从源码构建） |
| GitHub Releases | 只到 `v3.14.3` | ✅ 同上（= main） |
| 官方 CDN `manifest-linux-{x64,arm64}.json` | **3.14.5**（`77a4cb9cf96c`） | ❌ 见下 |
| 官方 CDN `manifest-*` | 3.14.4 也存在 | ❌ 同上 |

仓库 `upstream.version` 钉的就是 `29628c9acd`，即 **GitHub 侧公开的最新提交**，因此
「同步上游最新版」在可构建范围内**已经是最新**。

## 为什么 3.14.5 拿不到

CDN 的 `manifest-linux-x64.json` 是**公开可读**的，列出了 7 个组件的 `artifactPath`
与 sha256：

```
server-bundle : v3.14.5+77a4cb9cf96c   →  components/linux-x64/server-bundle/v3.14.5+77a4cb9cf96c.tar.gz
node-pty      : v1.2.0-beta.10+524740883ddc
glm           : v0.13.3+04947e21cce0
node-runtime  : v22.16.0+7d37ff1b4544
bfs / ripgrep / ugrep ...
```

但组件 tarball **全部 404**，试过的路径（均 404）：

- `.../releases/3.14.5/components/linux-x64/server-bundle/<ver>.tar.gz`
- 同上，但 `+` 分别用 `+` 与 `%2B`
- `.../releases/3.14.5/artifacts/...`、`.../electron/artifacts/3.14.5/...`
- `.../electron/components/...`、`.../zcode/components/...`
- 去掉 arch 段、去掉 `components/` 段的各种组合

另外 `77a4cb9cf96c` 在公开仓库里 **查不到**（GitHub API 返回 `No commit found for SHA`），
说明 3.14.5 是**内部构建**，源码尚未 push 到公开 `main`（公开 main 仍停在 3.14.3）。

## 试过的替代路径：桌面版 deb

`https://cdn-zcode.z.ai/zcode/electron/releases/3.14.5/linux-x64/ZCode-3.14.5-linux-x64.deb`
**可以下载**（162 MB）。但它是 **Electron 桌面应用**，内部结构是：

```
opt/ZCode/{zcode 可执行文件, *.so, locales/, resources/}
opt/ZCode/resources/app.asar          (327 MB，27059 个文件)
opt/ZCode/resources/app.asar.unpacked/node_modules/{ssh2,node-pty}/...
opt/ZCode/resources/glm/...           (zcode-cua-plugin，含 koffi)
opt/ZCode/resources/config/           (内置 provider 配置)
```

拿它**拼不出 fpk 需要的 runtime 布局**：

| fpk 需要（Web runtime） | deb 里有吗 |
|---|---|
| `runtime/bin/zcode.mjs`（启动器） | ❌ asar 内无此文件 |
| `runtime/server/entry-http.js` | ❌ 无（只有 Electron main/preload/renderer/host/scheduler） |
| `runtime/agent/zcode.cjs` | ❌ 无 |
| `runtime/web/`（Vite 前端产物） | ⚠️ 有等价物 `out/renderer/`（index.html + assets + material-icons + pdfjs），**可尝试映射** |
| `runtime/node_modules/`（服务端闭包） | ❌ 只有打包后的 asar，非可 require 的目录树 |

也就是说：**前端部分 deb 里是有的，服务端/agent 没有**。硬拼的代价是「半个包」，
且 Electron 主进程的 server 宿主逻辑与 `zcode --web` 那条链路不同，风险与工作量都高于收益。

## 决策

1. **保持 3.14.3**：`upstream.version = 29628c9acd`，等于 GitHub 公开最新。
   CI 每次构建都从源码产出 runtime，可复现、可审计。
2. **3.14.5 不追**：源码未公开，组件包不可下，deb 无法组装成合法 runtime。
   强行基于 deb 拼装会得到一个「无法验证、上游一变就废」的包。
3. **等上游 push**：一旦 `zai-org/ZCode` 的 main 前进到 3.14.4/3.14.5，
   只需改 `upstream.version` 一行（CI 就会自动重建），本仓库无需其他改动
   —— 这正是「壳 + 可替换 runtime」设计的目的。
4. **本次 fpk 版本号升到 3.14.4**：因为打包内容有重大变更（网关接入层）。
   注意飞牛用 `golang.org/x/mod/semver` 比较版本，**不能**写成 `3.14.3-1`
   （`-` 后缀被判定为 prerelease，比 `3.14.3` 更小，已装用户收不到升级），
   故用递增的补丁号。

## 复现命令（只读）

```bash
# 1) 上游公开最新（应与 upstream.version 一致）
git ls-remote https://github.com/zai-org/ZCode.git refs/heads/main

# 2) 官方 CDN 在发什么版本（公开可读）
for v in 3.14.3 3.14.4 3.14.5 3.14.6; do
  printf '%s: ' "$v"
  curl -s -o /dev/null -w '%{http_code}\n' \
    "https://cdn-zcode.z.ai/zcode/electron/releases/$v/manifest-linux-x64.json"
done

# 3) 组件包是否可下（预期 404）
curl -s -o /dev/null -w '%{http_code}\n' \
  "https://cdn-zcode.z.ai/zcode/electron/releases/3.14.5/components/linux-x64/server-bundle/v3.14.5+77a4cb9cf96c.tar.gz"
```

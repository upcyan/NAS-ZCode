# v3.14.4 发布说明（Release Notes）

> 打包修订版。内置 ZCode 运行时仍为上游 **3.14.3**（GitHub 公开最新），
> 本版主要解决**非局域网环境下打不开 / 连不上**的问题。

---

## 一句话

桌面图标不再走裸端口，改为**飞牛统一网关**入口 —— 现在用 **fnConnect / 手机 App / 外网**
打开 ZCode 也能正常用了，不用做端口映射，也不用把访问令牌塞进 URL。

## 为什么之前的版本远程打不开

旧版桌面入口是 `http://<NAS_IP>:8988`。而 fnConnect 等远程通道**只转发飞牛面板**
（`/app/` 网关），**不转发任意业务端口**，所以：

- 局域网内：一切正常；
- 非局域网（远程）：图标点开是白屏 / 「Web 启动失败 / WebSocket connection failed」。

根因不在令牌，而在**入口根本没走远程可达的那条路**。

## 本版怎么修的

接入飞牛统一网关（`ui/config` 的 `gatewaySocket` + `gatewayPrefix`），入口改为
`/app/zcode`。麻烦的地方在于 **ZCode 服务端不支持 basePath**——它的 `entry-http`
只认 `PORT` / `ZCODE_SERVER_HOST` / `ZCODE_WEB_STATIC_ROOT` / `ZCODE_SERVER_AUTH_TOKEN`，
没法自己挂在 `/app/zcode` 前缀下；前端也把资源与接口写成根绝对路径
（`/assets/…`、`/api/*`、`/ws`）。

所以包内新增了一个**网关接入层**（`app/gateway/`）：

| 文件 | 职责 |
|---|---|
| `gateway.mjs` | 监听应用目录下的 unix socket；剥掉 `/app/zcode` 前缀后转发给本机 server；转发 HTTP 与 WebSocket 升级；改写 HTML/CSS/JS 里的根绝对路径；去掉上游的 `X-Frame-Options` 与 CSP `frame-ancestors` 以便面板内嵌 |
| `url-compat.js` | 运行期接管 `fetch` / `XHR` / `WebSocket` / `EventSource` / `Worker` 与 `script.src` / `link.href`，把前端动态产生的根绝对路径拉回前缀下（仅在网关子路径下生效） |

其中「服务端文本改写」是必需的：HTML 里 58 处 `modulepreload`/`script`/`stylesheet`
与 CSS 里 59 处 `url(/assets/KaTeX_*)` 是**浏览器解析阶段**就发起的请求，JS 层拦截够不着。
而 `import("./chunk.js")` 是相对模块 URL 解析的，天然落在前缀下，因此不改写。

## 两条访问链路

|  | 桌面图标 / 远程（推荐） | 局域网直连 |
|---|---|---|
| 入口 | `https://<面板域名>/app/zcode` | `http://<NAS_IP>:8988` |
| 鉴权 | **面板登录态**（网关校验并注入 `X-Trim-Userid/Username/Isadmin`） | **访问令牌** |
| 端口映射 | 不需要 | 需自行放通 8988 |
| fnConnect 远程 | ✅ 可用 | ❌ 裸端口不可达 |

局域网直连与访问令牌机制**完全保留**，习惯直连的用户不受影响。

## 顺带修掉的两个坑

1. **入口令牌脚本在子路径下误判**：旧脚本把入口路径首段当令牌，而网关路径 `/app/zcode`
   的首段是 `app`，会被当成令牌写进 cookie → 服务端拿 `app` 去比对 → 鉴权失败（且比不带
   cookie 更难排查）。现在维护了一份保留首段清单（`app`/`assets`/`api`/`ws`/`share`/`cn`…），
   并同时支持 `/?token=` 与历史写法 `/<令牌>`。
2. **浏览器残留旧令牌**：网关转发时**覆盖**（而非追加）请求里的 `zcode_lite_token`。
   若追加成 `OLD; NEW`，服务端取第一个 → 仍拿旧令牌 → `/ws` 401。这正是旧版
   「换令牌/重装后报 WebSocket 连接失败」的成因，本版从链路上掐掉。

## 版本号说明

fpk 版本 `3.14.4`，内置运行时仍是上游 `3.14.3`。之所以升到 `3.14.4` 而**不是**
`3.14.3-1`：飞牛用 `golang.org/x/mod/semver` 比较版本，**带 `-` 的后缀会被判定为
prerelease（比 `3.14.3` 更小）**，已装用户会收不到升级。故必须用递增的补丁号。

## 安装 / 升级

- 新装：应用中心 → 手动安装 → `zcode-3.14.4.fpk`（会自动装上依赖 Node.js v22）。
- 升级：直接覆盖安装。**登录态、配置、工作区都在应用数据目录，不受影响。**
- 升级后建议从**飞牛桌面图标**打开（走网关）；若之前一直用 `IP:8988` 直连，也可继续沿用。

> 文件校验（大小与 SHA256）以 [Releases 页面](https://github.com/Kasbuky-sudo/NAS-ZCode/releases) 上该版本的说明为准
> —— 正式发布物由 CI 从上游源码重建，字节与本地试构建可能不同。

## 验证情况

- 本地从 fpk 提取网关后，用真实 Chromium 端到端跑通：72 个资源请求 **0 失败**、
  `/app/zcode/ws` **升级成功**、工作台**完整渲染**（侧边栏/项目/模型选择/输入框）、无启动错误。
- 局域网直连回归：无令牌 401、带 cookie 200、两种令牌形式 200、WS 101，全部正常。
- 旧令牌 cookie 覆盖回归：带 `STALE_OLD_TOKEN` 时 API 仍 200、WS 仍 101。
- CI：从上游源码构建 runtime → 打包 fpk → 包结构自检 → 网关冒烟测试，全部通过。

## 已知问题

- **arm64 机型仍未完成本机验收**（x86 已实测）。包内已带 arm64 预编译件，理论可用。
- 内置终端（node-pty）需登录后首次打开终端才加载，未逐一验证各机型 ABI。
- 套餐查询「获取失败」（上游接口返回 3001）为**上游服务端行为**，非本包问题，
  详见仓库 `docs/已知问题-套餐查询-3001.md`。
- 浏览器自动化（CUA）在 NAS 上不可用（依赖本机 Chromium），属可接受降级。
- 官方 CDN 已在发 3.14.5，但**源码未公开、组件包不可下载**，暂不追。
  详见 `docs/上游版本同步-3.14.5调研.md`。

## 安全提醒

- **请勿把 8988 映射到公网**。远程访问请走面板 / fnConnect（网关已带面板登录态校验）。
- ZCode Web 等于把一个**能执行命令的 AI agent 与终端**开放出去；令牌请用随机长字符串，
  不要用弱口令或与 NAS 登录密码相同的值。

## 修订记录（打包修复）

### 2026-10-09 修复「无法更新：执行脚本出错且原因未知」

**现象**：在应用中心对已装的 3.14.3 执行升级，进度停在停止服务之后，报
「执行脚本出错且原因未知」，应用停在未运行状态。事件日志记为
`APP_UPDATE_FAILED`（`REASON` 为空）→ `APP_CRASH`。

**根因**：**产物文件权限**，不是网关改动。

- 构建机的 `umask` 是 `0077`。`fnpack` **不会**把权限拍平，它原样保留 staging 里的
  权限位，于是打出的 fpk 内 `app.tgz` 是 `-rw-------`、`gateway/` 目录是 `drwx------`。
- 飞牛装包时以**应用运行用户**（`zcode`，非文件属主）解包与执行，读不到 `0600` 的
  `app.tgz`、也进不去 `0700` 的目录，脚本随即失败 —— 对应前端那句
  「执行脚本出错且原因未知」（错误码 `10271 ErrCodeResourceResouceExceptionUnknown`）。
- 对照官方 3.14.3 包（当时安装成功）：`app.tgz` 为 `-rw-rw-rw-`、目录 `drwxrwxrwx`，
  即**全员可读**。差异就在这里。
- 旁证：事件日志显示 **09-29（本次改动之前）** 用旧包升级同样 `APP_UPDATE_FAILED`
  两次，最后只能「卸载 → 重装」才成功；同一时间 dsh-fnos / CyanNVR 升级均正常
  （`APP_UPDATED`）。说明这是构建侧长期存在的问题，与网关无关。

**修复**：
1. `build.sh` 开头 `umask 022`，并在打包前把 staging 权限显式归一化为
   目录 `0755` / 文件 `0644`，可执行件（`cmd/*`、`*.node`、`*.cjs`）保持可执行位；
2. 新增**产物权限自检**：打包后扫描 tar 内权限位，出现「其他用户不可读」直接构建失败，
   不再等到真机升级才暴露；
3. 顺带修掉 CI「无 fnpack」打包分支漏拷 `wizard/` 的问题（会导致安装向导取不到
   `${wizard_path}`）。

**验证**：umask `0077` 环境下重建 → 包内 `app.tgz` 为 `-rw-r--r--`、目录 `0755`；
以非特权用户（nobody）解包对照，旧包解出的 `gateway/` 是 `drwx------`（进不去），
新包是 `drwxr-xr-x`；`install_callback` / `main status` 正常；CI（含包结构自检与
网关冒烟）全绿。

> 若你之前装的是有权限缺陷的那一版并已卡在失败状态，**卸载后重装**（或直接装本次
> 修复后的包）即可；用户数据在 `@appdata/zcode`，卸载时选择保留即可不丢登录态与工作区。

内置 ZCode 运行时：3.14.3（上游 GitHub 公开最新）。本次为打包修订。

## 更新内容

**支持远程访问**

桌面图标改走飞牛统一网关（`/app/zcode`），fnConnect、手机 App、外网都能打开，
不需要端口映射，也不用把访问令牌写进 URL。

旧版入口是裸端口 `http://<NAS_IP>:8988`，fnConnect 只转发面板的 `/app/` 网关，
不转发业务端口，所以远程打开是白屏，报「Web 启动失败 / WebSocket connection failed」。

局域网直连 `http://<NAS_IP>:8988` 与访问令牌机制保持不变。

**修复无法升级**

之前的包在应用中心升级会失败，报「执行脚本出错且原因未知」。
原因是 manifest 里 `install_dep_apps` 只写了应用名 `nodejs_v22`，没有版本约束，
升级时依赖校验通不过。已改为 `nodejs_v22>22.0.0`。

**修复打包产物权限**

构建机 umask 是 0077，打出的包内 `app.tgz` 权限为 0600，
安装后应用用户（非属主）读不到。现在构建时统一权限并在打包后自检。

**升级脚本**

`upgrade_init` 现在会先停服务并确认进程退出，避免残留进程占着应用目录导致升级中断。

## 安装

应用中心 → 手动安装 → 选 `zcode-3.14.4.fpk`（会自动装上依赖 Node.js v22）。

已装旧版直接覆盖安装。若之前卡在升级失败状态，可先卸载再装，卸载时选保留数据，
登录态和工作区都在 `@appdata/zcode`，不会丢。

## 已知问题

- arm64 机型未做本机验收，x86 已实测
- 模型设置里的套餐查询显示「获取失败」，属上游接口行为，与本包无关
- NAS 上无法使用浏览器自动化（依赖本机 Chromium）
- 官方 CDN 已在发 3.14.5，但源码未公开、组件包下载不到，暂时跟不了

## 注意

不要把 8988 端口映射到公网，远程访问请走面板 / fnConnect。

ZCode Web 等于把一个能执行命令的 AI agent 和终端开放出去，访问令牌请用随机长字符串，
不要用弱口令或与 NAS 登录密码相同的值。
